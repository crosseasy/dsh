# Agent Note: Lefthook wrappers carry the installing Node PATH

Status: implemented

English | [中文](2026-08-24-lefthook-node-path-bootstrap.zh.md)

## Problem

GUI Git clients can invoke hooks with a minimal system `PATH`. Worktree-local Lefthook wrappers can still start because the generated hook records an absolute Lefthook binary path, but the jobs in `lefthook.yml` rely on `node_modules/.bin/tsx` shebangs and `pnpm run typecheck`. When the Node/Corepack directory is missing from `PATH`, `pre-push` fails with `sh: pnpm: command not found` before typechecking starts.

## Decision

After `lefthook install --force` writes hook files into the owned worktree hook directory, `scripts/install-lefthook.mjs` rewrites each regular POSIX `#!/bin/sh` hook to prepend `dirname(process.execPath)` to `PATH` and export it. Windows hook files are left unchanged. The installer keeps the existing ownership checks and makes already-bootstrapped wrappers idempotent.

The exported directory is the Node toolchain that ran the installer, so Corepack-managed `pnpm` and `/usr/bin/env node` shebangs resolve for terminal and GUI Git clients. If that Node installation moves, running `node scripts/install-lefthook.mjs` regenerates the wrappers with the current path.

## Alternatives considered

**Put an absolute `pnpm` path in `lefthook.yml`.** Rejected because `lefthook.yml` is shared source while the pnpm executable location is per developer machine and per Node installation.

**Depend on shell startup files.** Rejected because GUI Git clients often do not run the user's interactive shell startup path, which is the observed failure mode.

**Disable `pre-push` for GUI clients.** Rejected because the fast incremental typecheck is the only local publication hook; losing it makes GUI pushes weaker than terminal pushes.

## Consequences

Generated POSIX hooks depend on the Node executable path used during installation, matching the existing absolute Lefthook binary generated by Lefthook. The installer regression suite checks the bootstrap in generated hooks, and a clean-shell hook invocation verifies that the local wrapper resolves `pnpm` before running `typecheck`.
