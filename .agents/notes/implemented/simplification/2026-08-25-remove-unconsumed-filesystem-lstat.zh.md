# Agent Note: 移除无消费方的文件系统不跟随链接操作

Status: implemented

[English](2026-08-25-remove-unconsumed-filesystem-lstat.md) | 中文

## 问题

`FileSystem.lstat` 与 `FsPathInfo` 要求每个文件系统提供方和每个测试提供方实现路径级元数据操作，且该操作不跟随最后一个符号链接。没有固定的生产消费方调用此方法。曾经消费该方法的指令发现功能根据[指令符号链接决策](../feature/2026-07-21-follow-instruction-symlinks.zh.md)，有意通过 `resolve` 与 `stat` 跟随符号链接，并把约束职责交给文件系统策略和沙箱。

这个未使用的操作还保留了仅供本地提供方使用的 `PathLinkInfo`、`pathLinkType` 与 `probeNoFollow` 代码、E2B 投影、专用测试、公共文档、类型等价条目和生成的 Cordis API 目录条目。

## 决策

文件系统 Service Definition 只通过 `stat(FsTarget, signal?)` 公开目标元数据，不公开路径级不跟随链接操作或 `FsPathInfo`。本地与 E2B 提供方实现文件系统工具及其他插件实际消费的十一个生产操作。

Node 与平台自身的 `lstat` 调用继续保留在保护原子发布、持久化检查、清理、可执行文件解析和文件系统发现等具体操作的位置。这些调用属于各自所有者的实现细节，不会恢复通用的 `ctx.fs` 操作。

## 考虑过的替代方案

- **为未来可能出现的安全消费方保留 `lstat`。** 否决，因为目前没有生产消费方定义所需的策略、错误语义或远程行为。未来的调用方必须先确立这些要求，才能增加提供方义务。
- **删除公共操作，但保留提供方专用的不跟随链接辅助函数。** 否决，因为本地与 E2B 辅助函数没有剩余调用方，只会留下不承载产品行为的代码与测试。
- **提供兼容别名或可选方法。** 否决，因为项目仍处于预发布阶段，而可选提供方方法只会把同一个缺少依据的决策转移给消费方。

## 后果

文件系统提供方和测试替身减少了一个必需方法，公共类型与生成的 API 目录不再宣传没有支持需求的不跟随链接元数据。既有文件系统读取、目录列出、变更、跟随符号链接的目标身份，以及独立的 Node/平台安全检查保持不变。

文件系统能力不再提供通用的最后路径组件符号链接检查。重新引入它需要固定的生产消费方，以及协调一致的 Service Definition、提供方、策略、文档和覆盖语义，不能只恢复推测性辅助函数。
