# `@deepseek-ai/dsh-curated-policy`

English | [中文](README.zh.md)

`@deepseek-ai/dsh-curated-policy` owns the checked-in curated plugin allowlist and exposes read-only policy queries through `ctx.curatedPolicy`.

The package loads the candidate lock, authoritative capability conflict rules, and permission rule seeds. Before publishing `ctx.curatedPolicy`, it computes the 100-point admission score from eight bounded dimensions, validates any declared total, requires every repository to be a credential-free canonical `https://github.com/<owner>/<repo>` URL, requires every reachable source to carry a normalized content digest, and requires active candidates to carry verified Node evidence, no core patch, a direct-tree digest, a runtime dependency closure digest, and complete `runtimeActivationEvidence`. Its profile keys must exactly equal `targetProfiles`; every profile value binds a keyless assembled snapshot and install, enable, restart, and disable-or-uninstall records to non-placeholder SHA-256 values, and its required bundle list must match the candidate declaration. All records and their artifacts are unique repository-owned tracked regular blobs in the [curated benchmark evidence directory](../curated-bench/evidence/README.md). The repository and DSH release `verify-curated-activation-evidence` gate traverses every profile value, requires all five records to name that map key, binds a canonical digest of the current template, active candidate set, install sources, config overrides, and artifact identities, and verifies `evidenceKind: observed`, the expected lifecycle operation, a successful command result, and exact candidate, source, installed-tree, runtime-closure, and required-bundle identities. Each record binds a separate artifact by path and SHA-256; that artifact repeats the repository, package, other identities, composition digest, operation, exact secret-free command argv, zero exit status, and observed success result. The argv must select the candidate/profile/operation test in a Git-tracked keyless snapshot, and the gate replays every selected test before activation or DSH release verification succeeds. The repository-owned snapshot producer remains trusted code rather than a cryptographically authenticated external attestation; review of that producer is part of accepting new evidence. Public diagnostics redact key/value secrets, Authorization values, scheme URL authority userinfo through its last `@`, and schemeless `user:pass@host:port` userinfo in candidate, profile, and path identifiers, where the host may be a DNS name or bracketed IPv6 literal; ordinary `@` characters outside those credential forms remain visible. Both command representations reject Authorization and Bearer values, `sk-*` tokens, secret-, token-, password-, key-, or cookie-shaped arguments, and URL userinfo in scheme URLs, option-assigned URLs, or schemeless `user:pass@host:port` values without echoing argv in diagnostics; ordinary candidate IDs and snapshot paths containing `authorization` remain valid. Environment variable names remain valid candidate configuration metadata, but executed evidence argv cannot contain their secret values. The production gate uses `git ls-files --error-unmatch --stage` and accepts only stage-zero regular-file modes, so package-authored evidence, ignored or untracked files, symlinks, `.git`, and `node_modules` paths cannot authorize activation. Every keyless assembled record and artifact must additionally report verified waterfall delegation and zero duplicate token injection or external requests; those are runtime observations, while preflight only checks the candidate's catalog-declared listener and resource claims. Policy loading also requires every runtime bundle to be provided by another active candidate with activation evidence in the same profile, validates provider/fallback relationships and profile conflicts, rejects secret-like metadata, and checks permission policy structure and ordering. Malformed YAML diagnostics retain the parser reason, redacted file identity, one-based line and column, caret, and non-secret code-frame lines without attaching the parser exception that retains the original source; quoted-key decoding identifies escape-obscured secret keys, comment-only lines do not end pending secret scalar continuations, and retained code frames receive a second scalar-redaction pass. The curated command package separately validates fail-closed settings in resolved permission artifacts and profile config. The Cordis plugin registers the service with an effect, so unloading the plugin removes `ctx.curatedPolicy`.

## Service Contract

`CuratedPolicy` freezes the parsed catalog and returns immutable candidate arrays. `listCandidates()` returns every audited candidate in catalog order. `getProfileCandidates(profileId)` returns only active candidates assigned to the requested profile, also in catalog order. `deriveCandidateStatus(candidate)` returns `active`, `qualified`, `pending`, or `rejected` from the active flag, artifact digests, and blocker codes; every inactive checked-in candidate must carry at least one blocker record.

`pnpm run audit-curated-candidates -- --candidate <id>` fetches one pinned commit into a temporary bare Git repository under a 50-second total deadline. Git receives only required launch, locale, proxy, certificate, and temporary-directory variables; inherited `GIT_*` and credential-shaped variables cannot redirect the repository, object database, or configuration. On POSIX, timeout or output overflow terminates the isolated process group and waits for it to disappear before deleting the temporary repository; Windows rejects before spawn because the local provider cannot prove Job Object-backed tree quiescence. The command reads the commit through `ls-tree` and `cat-file --batch`, never creates a checkout, and rejects non-blob entries, unsupported modes, and non-portable paths. The digest starts with `dsh-source-content-v1\0`, sorts all entries by UTF-8 POSIX relative path bytes, then hashes the mode, object type, path, and blob bytes with an unsigned 64-bit big-endian byte length before each component. A symlink therefore hashes its `120000` mode and link-target blob bytes without following the target.

`validateCandidateLock(catalog)` checks deterministic catalog assertions: schema version, full Git SHAs, canonical GitHub repository URLs, a required `sourceContentSha256` for each `verified` source, exact SemVer 2.0 npm versions paired with canonical non-placeholder 64-byte SHA-512 SRI values, required installed-tree and runtime-dependency-closure digests, exact activation-evidence profile coverage for active candidates, declared source status, Node and core-patch fields, rejection of active Git lifecycle builds, candidate IDs, explicit blockers for every inactive candidate, profile-overlapping active resources, and secret-like material. `hasCompleteCurrentProfileActivationEvidence(candidate, profileId)` exposes the same exact profile/evidence keys, required-bundle identity, safe-path, and non-placeholder SHA-256 checks used for profile dependency materialization. Exact versions may contain valid prerelease and build metadata; ranges, tags, leading `v`, empty identifiers, and numeric prerelease identifiers with leading zeroes are invalid. `isExactNpmVersion()` exposes that rule to curated consumers. The source digest identifies the pinned Git tree rather than GitHub's changeable source-archive encoding. `validatePolicySemantics(catalog, conflicts, permissions)` checks referenced providers, fallback capabilities, unmanaged providers, permission rule IDs, and every configured profile. `permissions.order` must exactly equal `core-sandbox`, `permission-rules`, `high-risk-approval-or-auto-review`, `tool-execution`, `result-audit`; missing, extra, duplicate, or reordered stages are invalid. Plugin loading, focused unit tests, and the repository `verify-curated-activation-evidence` gate retain the static checks. The package invariant is an explained empty installer because fixed catalogs expose no runtime relationship to observe.

## Model Experience

### Curated policy service

#### What the model sees

`ctx.curatedPolicy` is a same-process query service for plugins and commands. It registers no prompt text, tool schema, user message, assistant-visible result, or session event.

#### Token effect

Zero direct token cost from `@deepseek-ai/dsh-curated-policy`.

#### KV Cache effect

No direct cache effect; a caller that turns policy data into prompt text or tools owns that model-visible registration.

## Known Limitations and Deferred Work

- **Catalog validation is not upstream evidence**: the allowlist records audit assertions, and the policy package checks their consistency without fetching or re-auditing upstream repositories. Observed artifact evidence requires a separately supplied exact-commit Git installation or exact-version npm installation with matching registry integrity, plus installed bytes matching the catalog tree digest.
- **Unverified runtime behavior stays inactive**: the 12-candidate `web-curated` target has six static/install qualification candidates and zero runtime-active candidates. Each qualification candidate records `assembled-keyless-snapshot-missing`; web search also declares and records its missing required browser runtime bundle. An inactive candidate may omit `runtimeActivationEvidence`. Activation requires the complete machine-validated evidence object and a successful repository evidence-file gate; removing rejection entries and setting `active: true` is insufficient.
- **Git lifecycle builds are prohibited**: an active Git dependency may not declare `preinstall`, `install`, `postinstall`, `prepare`, or `prepack`. A candidate can instead name a verified exact npm version and integrity; the policy records its published lifecycle fields but does not execute them during validation.
- **No profile writing or permission execution**: profile materialization belongs to `@deepseek-ai/dsh-curated-profiles`, CLI reporting belongs to `@deepseek-ai/dsh-curated-scripts`, and tool authorization remains delegated to the selected permission plugin. The curated layer validates that plugin's fail-closed artifact and profile configuration.
