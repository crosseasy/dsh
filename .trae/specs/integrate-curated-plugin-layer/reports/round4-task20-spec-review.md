# Task 20.1 Independent Specification Review

Verdict: **NOT APPROVED**

## Findings

### P1 (confidence 10/10): rollback output can identify snapshots for an unrelated profile

The approved requirement says a threshold breach must return rollback state for the previous lock and profile (`.trae/specs/integrate-curated-plugin-layer/spec.md:144-147`). `readRollbackSnapshot()` only requires a non-empty `snapshot.profile` (`packages/curated/curated-scripts/src/index.ts:2066-2107`), while comparability validation checks run environments and task/attempt sets without binding either embedded snapshot to the baseline profile or its `lockSnapshot`/`profileSnapshot` references (`packages/curated/curated-scripts/src/index.ts:2146-2175`). `compareBenchmark()` then returns those unbound snapshots unchanged as rollback data (`packages/curated/curated-scripts/src/index.ts:2226-2251`). A structurally valid observed comparison for `web` versus `web-curated` can therefore return `rollback` with lock/profile snapshots naming another profile. Bind both embedded snapshot profiles and references to the compared baseline before emitting an actionable rollback result.

### P1 (confidence 10/10): completed checklist claims contradict the current old-path and fault evidence

The checklist marks all local fault cases, including browser failure, complete and marks the official Web/headless, tool pipeline, permission interaction, and session wire invariants complete (`.trae/specs/integrate-curated-plugin-layer/checklist.md:20-21`). The same checklist's current strict section leaves the command matrix and old-invariant evidence pending (`.trae/specs/integrate-curated-plugin-layer/checklist.md:52-57`). The fresh negative-path report states that browser crash has no local fixture and remains planned (`.trae/specs/integrate-curated-plugin-layer/reports/round4-verification-bench-negative.md:97-102`). The fresh CLI report states that its Web command used `--help`, did not start the server or browser, and therefore did not exercise browser handoff (`.trae/specs/integrate-curated-plugin-layer/reports/round4-verification-cli-docs.md:71-83`), although the required old Web path explicitly includes startup, URL printing, and browser handoff (`docs/plugin/superpowers/00-背景与目标.md:54-62`). Keep these items pending or add the missing runtime evidence; the earlier completed claims cannot remain checked.

### P1 (confidence 9/10): active model-visible profile behavior has no assembled snapshot or real candidate execution

The shipped templates activate six third-party bundles (`packages/curated/curated-profiles/src/index.ts:41-48`), and the package documentation acknowledges that those loaded bundles can add model-visible prompts, tools, or results (`packages/curated/README.md:29-43`). Repository policy requires every non-trivial model-, protocol-, or human-visible change to add or update a keyless runnable-example snapshot and explicitly says package tests, mock compositions, and PR rationale are not substitutes (`docs/testing.md:47-49`). The only tool/approval/session regression boots a repository-owned behavior fixture (`packages/curated/curated-profiles/tests/profiles.spec.ts:1228-1275`), while Task 18 explicitly leaves assembled third-party snapshots pending (`.trae/specs/integrate-curated-plugin-layer/task-18-report.md:151-156`). No `web-curated` snapshot scenario exists under the repository snapshot suites. Add an assembled keyless scenario for the active profile behavior, or keep runtime admission incomplete rather than treating the six candidates as fully accepted product behavior.

### P2 (confidence 10/10): three curated invariant companions enforce static facts as runtime invariants

Repository policy permits a non-empty invariant only for an event-stream or mutable-data relationship; fixed configuration and pure examples belong in load or unit tests, otherwise the installer must be empty with an owner-specific explanation (`.agents/notes/implemented/architecture/2026-07-19-package-invariant-runtime-contracts.md:17-24`). `curated-policy` revalidates fixed YAML catalogs (`packages/curated/curated-policy/src/invariant.ts:26-53`), `curated-profiles` revalidates constant templates and dependency declarations (`packages/curated/curated-profiles/src/invariant.ts:21-48`), and `curated-bench` revalidates static JSON assets (`packages/curated/curated-bench/src/invariant.ts:27-46`). These checks have no runtime observation relationship and duplicate existing package tests/load validation. Convert them to justified empty companions and retain the checks in their existing focused tests.
