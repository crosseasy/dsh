# 设计：辩证优化 superpowers 文档（吸收深度调研蓝本）

> 本 spec 与配套 plan 是 Ralph 要求保留的执行依据。本轮不执行 `git add`，且不改变任务开始前既有 index。

## 1. 背景与问题

`docs/plugin/superpowers/` 现有 7 篇文档描述**当前实现**。仓库持有固定 SHA 的 catalog、profile 模板、planned 评测资产和本地 fixture 定义；6 个静态/安装资格候选均缺少真实固定产物的 keyless assembled runnable snapshot，runtime active 数为 0。它们引用的飞书蓝本是《高质量插件集成与评测方案》（§1–§9 结构，快照 2026-08-24）。

作为复评输入的飞书文档是**另一篇更深的研究**：《DeepSeek Harness 插件生态深度调研与集成技术方案》（一–六 结构，2026-08-25），其插件级结论**显式止于 E1**（"结论止于静态核验层，需按文中流程完成实测方可定档"）。

**核心张力**：新蓝本的择优结论与当前策略状态存在分歧（如 dsh-context 被飞书 E1 选入、却因缺少 Node 证据在当前 allowlist 中被拒绝）。若直接替换会破坏事实基线。

**设计原则**：保留当前实现为事实基线；将飞书内容用于强化三层门禁、E0–E5 证据体系、候选复评；**不直接替换现有 profile 与准入结论**。

## 2. 证据层级是全部设计的支点

| 层 | 飞书 E 级含义 | `evidenceKind` 关系 | 对账规则 |
|---|---|---|---|
| E0 | README 自述，未验证 | 任一标签都不能自动排除 E0 | 只作发现信号 |
| E1 | 固定 SHA 静态源码/manifest | `planned` 只表示未运行，不能自动满足 E1 | 飞书插件结论止于此 |
| E2 | 可复现构建、类型检查、扫描 | `fixture` 只描述来源；具体证据充分时可支持 E1/E2 | 标签本身不升级 |
| E3 | 隔离 DSH_HOME 装/启/重启/卸 | `observed` 是操作者自报 | 必须另有生命周期运行产物 |
| E4 | 真实用户路径产出文件/UI/日志 | `accepted` 只表示结构、可比性与阈值通过 | 必须另有用户路径产物 |
| E5 | 异环境/版本/模型复现 | 没有对应标签 | 必须由另一环境独立复现 |

**证据结论**：E0–E5 与 `evidenceKind` 没有一一映射。飞书插件结论止于 E1，当前 allowlist 也只持有策略、静态与安装资格结论；候选初始化、启用、重启、禁用或卸载及用户路径证据均为 pending。两侧分歧保持待定，直至取得对应等级的具体证据；E5 还要求独立环境复现。完整定义由 [06](../06-深度调研复评与证据分级.md) 持有。
