## 2. E0–E5 证据分级与 `evidenceKind`

深度调研补充采用 E0–E5 证据阶梯。[04 §7](04-评测体系.md) 的 `evidenceKind` 描述 benchmark 输入的声明来源或执行状态，不是 E 级证书，两者没有一一映射：

| E 级 | 含义 | 可用工具（补充列举） | 与 `evidenceKind` 的关系 |
|---|---|---|---|
| E0 | 作者自述、README 声明，未验证 | —（清单描述仅为 E0） | 任一标签都不能自动排除 E0 |
| E1 | 固定 SHA 上的静态源码/manifest 检查 | dsh-quality-score、dsh-dep-audit | 由具体静态证据证明；`planned` 只表示尚未运行，不能自动满足 E1 |
| E2 | 可复现构建、类型检查、静态扫描 | dsh-poison-guard、doctor audit | `fixture` 只描述来源；充分的 fixture 内容可支持 E1/E2，标签本身不升级 |
| E3 | 隔离 DSH_HOME 下装/启/重启/卸 | dsh-test-drive、dsh-effect-doctor | `observed` 是操作者自报，不能独立证明生命周期运行 |
| E4 | 真实用户路径，产出文件/UI/日志/外部态 | dsh-plugin-verify、dsh-eval | `accepted` 是结构、可比性与阈值结果，不能独立证明用户路径 |
| E5 | 独立复现者在另一环境/版本/模型上重跑 | 人工二次验证 | 必须由独立环境复现；没有对应的 `evidenceKind` 标签 |

**关键口径**：`planned` 只表示未运行，`fixture` 只描述输入来源，`observed`、producer metadata 与运行字段由操作者提供，`accepted` 只表示输入通过结构、可比性和阈值检查。任何标签都不能代替相应 E 级要求的具体产物。真实 E3/E4 必须独立保留来源信息，以及对应的安装、启用、重启、禁用或卸载与用户路径实际运行产物；E5 还要求另一环境的独立复现。

当前仓库持有固定 SHA、源码内容摘要、安装目录摘要、runtime 依赖闭包、profile 模板、planned 评测资产和 fixture 定义。`dsh-web-search-pro`、`dsh-memento`、`dsh-mcp-panel`、`dsh-checkpoint-rewind`、`dsh-lsp-actions` 与 LoongSuite OTel 是静态/安装资格候选，不是 runtime 已交付候选；六者均缺少真实固定产物的 keyless assembled runnable snapshot，`dsh-web-search-pro` 还缺少必需的 `@anweat/dsh-browser` bundle/runtime dependency。Runtime active 数为 0。每个候选只有在真实固定产物、keyless assembled snapshot、全部必需依赖 bundle，以及安装、启用、重启、禁用或卸载证据全部齐备后才能转为 active。E3/E4、搜索、记忆、浏览器、MCP、故障注入、A/B 与 canary 均为 pending。

## 4. 指标体系补充视角

深度调研补充的评分设计可作为 [04 §1](04-评测体系.md) 静态 100 分与 §3 动态择优的**补充视角**，不替换现有评分：

- **门禁项不给分**：不满足直接淘汰（可激活性作淘汰制门禁），避免"功能强但装不上"被高分掩盖。
- **人气项不进分**：本生态星标已被证明失效（见 [00 §1](00-背景与目标.md) 的实测数据）。
- **无证据维度剔除后归一**：`总分 = Σ(维度得分 × 权重) / Σ(有证据维度的权重)`，并同时输出**覆盖率**；覆盖率 < 80% 标记为 provisional / 不排名。
- **硬性上限**：确认的干净安装失败 → 总分上限 39；确认的核心路径失败 → 上限 49；未披露的重大边界越权 → 直接判 UNSAFE。

> 上述阈值沿用深度调研补充引用的披露式治理阈值，作者本人声明"是公开的试点治理阈值，而非统计最优常数"。本目录同样不主张其统计最优性，价值在于公开可审、跨插件一致。

## 5. 方法论边界声明

深度调研补充明确的方法论边界，本目录一并继承：

- 投毒扫描无法证明代码无恶意（Rice 定理，检测任意恶意行为不可判定）；真正的运行时边界是部署所选的既有 `ctx.sandbox` provider 与其明确配置。本目录不得用未映射到 DSH 配置的外部模式名冒充已实施的约束，也不得在没有真实沙箱证据时声称候选已隔离。
- effect-doctor 类工具只覆盖 Cordis 托管资源；裸 JS 定时器、DOM 监听、原生句柄、外部进程不在范围内。
- mock-llm 无法激活依赖 Web UI 的插件，这类记为"非插件缺陷"的信息项（ⓘ）而非失败。
- 每个插件的测试用例至少一组**正例** + 一组**反例** + 一组**卸载用例**；安全护栏类插件反例比正例更重要（一个把所有命令都拦下来的插件在正例上表现完美）。

## 6. 局限（复评自身的边界）

- 深度调研补充未做真实安装验证，插件级结论止于 E1；本篇的复评对照据此均为"候选推荐 + 待定档"，不改变 [02](02-插件矩阵与择优.md) / [03](03-实施路线图.md) 的当前准入。
- 星数与活跃度是 2026-08-25 单点快照，在日更生态中快速漂移。
- 功能聚类基于 README 关键词语义，未逐个读源码验证功能等价性——这正是需要 E4 级验证的原因。
