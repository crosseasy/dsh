# 04 · 评测体系与择优指标

对应飞书蓝本 §6（评测体系与择优指标）。

评测分两部分：**静态准入**（能否进候选池）与**动态择优**（同类插件谁胜出）。星标只用于发现和社区信号，不能补偿安全、兼容或效果缺陷。

## 1. 静态准入：100 分

| 维度 | 权重 | 测量项 | 硬门槛 |
|---|---|---|---|
| DSH 原生兼容 | 20 | `dsh.bundle.patch`、Node engine、无需改核心、profile 可安装、HMR 可卸载 | 无 bundle 或要求核心补丁直接拒绝 |
| 功能完整性 | 15 | 核心流程覆盖、失败语义、配置项、可观测性、导入导出 | 主流程必须可自动验证 |
| 测试与 CI | 15 | 单测、集成、安装 smoke、跨平台、发布校验 | 默认插件至少有自动测试或可复现 smoke |
| 安全与隐私 | 15 | 最小权限、fail-closed、凭证处理、路径围栏、外发控制、审计 | 存在明文凭证或默认越权直接拒绝 |
| 维护健康 | 10 | 最近提交、发布节奏、issue 响应、破坏性变更说明 | 归档或长期不可构建拒绝 |
| 性能成本 | 10 | 启动耗时、RSS、prompt/schema token、后台任务、外部请求 | 超过 profile 预算不得默认启用 |
| 可运维性 | 10 | 版本锁、升级、备份、回滚、诊断、日志 | 无法单插件禁用或回滚不得默认启用 |
| 社区信号 | 5 | 插件自身星标、fork、用户反馈、采用案例 | 只加分，不做硬门槛 |

### 1.1 评分档位

- ≥85 分 → 进入**默认候选**
- 75–84 分 → 进入**场景候选**
- 65–74 分 → 仅**实验**
- <65 分或命中硬拒绝项 → **不纳入**

父仓库星标最多计 2 分；插件子目录必须独立评估。

### 1.2 静态准入叶级门禁

静态准入映射到 [03 路线图](03-实施路线图.md) 的脚本门禁，均为秒级命令：

- DSH 原生兼容 → `verify-lock.mjs` 校验 `dsh.bundle.patch` 存在、Node engine 匹配、无核心补丁
- 测试与 CI → 克隆核验测试文件数与 CI 工作流数（记录到 benchmarks 清单）
- 安全与隐私 → preflight 扫描凭证明文与默认越权
- 可运维性 → smoke-profile 验证可单插件禁用与回滚

## 2. 既有系统回归矩阵（不变量验收）

> 依据 superpowers 系统演进护栏：新功能 smoke 不能替代既有用户路径验收。以下矩阵锚定 [00 §4.2](00-背景与目标.md) 的既有用户路径不变量，每接入一个能力域后必须全绿。

### 2.1 既有用户路径回归矩阵

| 既有路径 | 验收方式 | 叶级门禁命令 | 通过判据 |
|---|---|---|---|
| Web 启动与 URL 打印 | smoke | `node .../smoke-profile.mjs --profile web-curated 2>&1 \| grep "dsh web:"` | 打印 URL 行 |
| headless 一次性任务 | dump-config | `pnpm dsh --profile headless --help >/dev/null 2>&1 && echo ok` | `ok` |
| 工具执行管线 | dump-config diff | `diff <(pnpm dsh --profile web-curated --dump-config) /tmp/官方web-dump.txt \| grep -c "tools/pre-execute"` | 顺序/数量符合预期 |
| 权限/审批交互 | preflight | `node .../preflight.mjs --profile web-curated 2>&1 \| grep -i permission` | 无冲突 |
| 会话导出 | 子包校验 | `node .../verify-lock.mjs 2>&1 \| grep session-export` | 只装子包 |

### 2.2 Web 回归（CDP 9333，用户规则第 0 条）

侵入 UI 的插件（如 `DSH-better-sidebar`）须做 Web 回归，必须用 Chrome + CDP 端口 9333，禁止 IDE 内置浏览器：

- [ ] 启动后 CDP 连通性：`curl -s http://localhost:9333/json/version | grep -q Browser && echo "cdp ok"`
- [ ] 控制台无 error（有 error 须修复）
- [ ] 既有面板/URL/handoff 未被新面板挤占或改写

## 3. 动态择优：任务效果优先

动态总分构成：

```text
任务成功率 30% + 结果质量 20% + 安全正确性 15% + 可靠性 15%
+ 性能与成本 10% + 操作体验 5% + 升级兼容 5%
```

同类插件在**相同** DSH、模型、prompt、workspace、网络和随机种子下做 A/B；任务顺序随机化，每任务至少重复 5 次，报告均值、P50、P95 和失败分布。

### 3.1 非补偿门槛（一票否决，不论总分多高）

- 安全正确性 < 95%
- 数据丢失事件 > 0
- 无法回滚
- 启动失败率 > 1%
- 关键任务成功率下降 > 3 个百分点

## 4. 各能力域测试方法

| 能力域 | 任务集 | 核心指标 | 关键负向测试 |
|---|---|---|---|
| 搜索 | 时效事实、技术文档、中文社区、深层页面、受限页面 | Recall@10、事实准确率、正文抽取成功率、P95 延迟、单任务请求数 | 引擎超时、重复结果、恶意网页注入、无 Key 降级 |
| 记忆 | 偏好、项目事实、决策、冲突事实、遗忘请求、跨项目隔离 | Recall@5、Precision@5、错误注入率、过期事实率、token 开销 | 提示注入记忆、跨空间泄漏、删除后召回、并发写冲突 |
| 多 Agent | 可并行工程任务、依赖 DAG、长任务、取消、恢复 | 完成率、墙钟时间、token 放大倍数、重复工作率、合并冲突率 | 子 Agent 崩溃、循环委托、超预算、父会话中断 |
| 浏览器 | 登录前页面、表单、下载、SPA、跨标签、人工接管 | 动作成功率、元素定位准确率、恢复率、每步延迟 | 弹窗、重定向、文件上传、错误窗口、页面注入 |
| 工程工具 | 诊断、重命名、回滚、diff 审阅、跨语言项目 | 诊断准确率、误改率、回滚完整率、修复后测试通过率 | 脏工作区、子模块、大文件、符号链接、并发修改 |
| 安全 | 路径越界、命令注入、凭证读取、网络外发、审批绕过 | 拦截率、误报率、fail-closed 率、审计完整度 | 规则文件损坏、审查模型不可用、编码混淆、工具别名 |
| UI/客户端 | 长会话、并发工具、移动窗口、弱网、刷新恢复 | 交互成功率、渲染帧稳定性、崩溃率、可访问性 | 重复 slot、主题切换、断线重连、超长日志 |
| 可观测性 | 正常、失败、取消、重试、子 Agent、后台任务 | span 完整率、父子关系正确率、开销、脱敏率 | 后端不可用、缓冲区满、敏感正文、进程退出 |

## 5. 代表性同类 A/B

| 对比 | 规模 | 统计口径 |
|---|---|---|
| `dsh-web-search-pro` vs `dsh-free-web-search` | ≥100 查询 | 时效/技术/中文社区/深页四子集 |
| `dsh-memento` vs `dsh-mneme` | 7 天、200 事实 | 20 次冲突更新 + 20 次删除请求 |
| `dsh-computer-use` vs `dsh-tabbit` | 同 50 个 Web 任务 | 成功率、接管、隔离、恢复 |
| `dsh-mcp-panel` vs `dsh-mcp-manager` | — | OAuth、静态 token、服务异常、profile 写入、回滚 |
| `dsh-cost-meter` vs `TokenLedger` | 固定请求日志 | 价格、缓存 token、时区、订阅额度 |

## 6. 回滚线

任一触发即自动恢复上一版 lock 与 patch：

- 启动失败率 > 1%，或插件导致 DSH 无法进入设置页。
- P95 首 token 延迟增加 > 15%，或空会话系统 prompt / 工具 schema token 增长 > 20%。
- 单任务成本增加 > 20%，但任务成功率提升 < 3 个百分点。
- 任意路径越界、凭证泄漏、未授权外发、无法恢复的数据损坏。
- 插件升级后无法通过 profile smoke、配置迁移或会话重放。

### 6.1 回滚线叶级门禁

- 启动失败率 → `smoke-profile.mjs` 连续 N 次退出码统计
- prompt/schema token 增长 → `--dump-config` 对比官方基线 token 数
- 成本增长 → `dsh-cost-meter` 或 benchmarks 记录的单任务 token 对比

## 7. 评测执行落地

评测资产落在 [01 §2.2](01-目标架构.md) 的 `packages/curated/curated-bench/`：

- `manifests/`：每个候选插件的克隆核验清单（测试数、CI 数、许可证、bundle 声明、审计时间）。
- `tasks/`：各能力域任务集（§4）。
- `baselines/`：官方 profile 与精选 profile 的启动指标、A/B 结果、回滚线基准。

比较脚本 `compare-benchmark.mjs`（见 [03 路线图](03-实施路线图.md) 脚本清单）读取 `baselines/`，输出同类插件的均值/P50/P95/失败分布与非补偿门槛判定。
