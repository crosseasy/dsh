# 00 · 背景与目标

对应飞书蓝本 §1（调研范围、口径与关键结论）与 §9（最终建议）。

## 1. 背景与调研口径

- 候选全集：Awesome DeepSeek Harness 中文清单，20 个主分类、630 条记录、620 个唯一 GitHub 仓库。
- 核验方式：第一轮抓公开仓库星标/归档/提交规模；第二轮对 46 个重点候选做浅克隆，核验最新提交、`package.json`、`dsh.bundle.patch`、Node 版本、许可证、测试文件、CI 工作流与已知限制。
- 快照日期：2026-08-24。星标只用于发现候选，**不作为准入依据**；大型父仓库星标 ≠ 子插件成熟度。
- 运行环境：DSH 处于 developer preview，蓝本记录根包版本 `0.1.1-rc.2`，要求 Node.js `^22.19.0 || >=24.0.0`。

## 2. 关键结论（决定整份计划的形状）

1. 不构建"全家桶"，而是建立可锁版本、可回滚、按能力域互斥的**精选插件层**；默认栈 12–16 个，其余进场景包或实验池。
2. 同一能力域最多保留一个默认 provider；第二个只能作为显式 fallback，不能同时向 `ctx`、工具注册表或 UI slot 注册同名能力。
3. 安全策略顺序固定：**确定性规则先行 → AI 审查补充 → 沙箱兜底**；LLM 审批不能替代规则引擎。
4. 冲突最高的五类：记忆、上下文压缩、浏览器、搜索、远程运行时，必须互斥 profile 或能力开关。
5. UI 美化、趣味插件、IM 通道、领域技能不进通用默认栈，只进独立场景包。

## 3. 本计划的落地目标

在**当前 monorepo 内**新增一组 `@deepseek-ai/dsh-*` 包，实现蓝本描述的 `dsh-curated` 精选层：

- **不改核心**：DSH 核心（模型适配器、工具、会话、Agent loop）保持不变，只通过 documented seams 扩展。
- **产出物**：一个内部精选 bundle + 多个 profile + 准入策略文件 + 评测基线 + 校验脚本（详见 [01-目标架构.md](01-目标架构.md)）。
- **遵循仓库既有约定**：新增包严格按 [docs/cookbook/adding-a-package.md](../../cookbook/adding-a-package.md) 的清单创建，bundle/profile 走 [app-boot Profiles](../../../packages/boot/app-boot/README.md#profiles) 契约。

### 3.1 落地形态说明（与蓝本的差异）

蓝本把 `dsh-curated` 描述为一个**独立下游发布单元**（消费 DSH 的外部项目）。本计划按用户决策改为**在当前 monorepo 内新增 packages**，因此：

- 蓝本目录树中的 `dsh-curated/` 根，映射为 monorepo 内的一个新包组 `packages/curated/`（纯容器目录，见 [01-目标架构.md](01-目标架构.md)）。
- bundle 的依赖锁不再依赖外部 npm 发布，而是走 workspace 内部依赖 + 对**第三方外部插件**的精确版本/SHA 锁。
- 第三方外部插件仍是外部依赖，通过 profile 的 out-of-tree `dependencies` 安装并锁定。

## 4. 既有系统不变量清单（禁止触碰）

> 依据 superpowers 系统演进护栏：向既有系统增能力时，当前行为是契约而非背景。以下不变量在整个执行过程中必须逐项保持不变；实现与 review 必须逐项举证未破坏。

### 4.1 核心运行时不变量

- **Agent loop 语义不变**：不修改 `packages/core/agent-loop`；新能力只挂 documented 扩展点（[docs/architecture.md](../../architecture.md)）。
- **会话日志契约不变**：`SESSION_FORMAT_VERSION` 不因本层变动；任何模型可见输入若新增，必须走既有 session event 机制（"模型可见 ⟺ 可从会话日志重建"）。
- **既有 profile 不被改写**：不直接修改官方 `web`/`headless` profile；精选层是**新增** profile，官方 profile 保持可用。
- **capability seam 完整性**：新增能力若是可替换能力，必须成套提供 Service Definition / Provider / Consumer 三角色，不得只加其一。
- **注册即副作用**：所有贡献走 `ctx.effect()` / `ctx.on()`，registry 的 `register()` 返回 disposer；HMR 卸载可逆。

### 4.2 既有用户路径不变量（回归矩阵锚点）

以下既有用户路径在接入任何插件后必须仍可用，作为 [04-评测体系.md](04-评测体系.md) 回归矩阵的锚点：

- Web 界面启动、URL 打印与浏览器 handoff（[web-app bundle](../../../packages/bundle/web-app/README.md)）。
- headless 一次性任务模式（[headless bundle](../../../packages/bundle/headless/README.md)）。
- 既有工具执行管线（`tools/pre-execute` → 执行 → 结果）语义与顺序。
- 既有权限/审批交互（`packages/interaction`）。
- 既有会话导出/持久化（`packages/session`）。

### 4.3 冲突高发区的强约束

- 记忆、上下文压缩、浏览器、搜索、远程运行时**同域最多一个默认 provider**；第二实现只能显式 fallback。
- 自动压缩、自动记忆、自动继续、自动审批**禁止一次性同时开启**，必须分别评估。

## 5. 全局约束（每个任务隐含包含）

- **不改核心**：任何要求修改 DSH 核心、无 bundle 声明、许可证不清晰、安装脚本越权、Node 版本不匹配的插件一律拒绝。
- **版本锁**：npm 包锁精确版本；GitHub 包锁完整 commit SHA；禁止无约束 `latest`。
- **叶级门禁**：每个验收步骤是一条耗时 < 1 分钟、可独立判定的命令（用户规则第 1、3 条）。
- **不提交计划文档**：本目录所有 markdown 不进 git（用户规则第 2.4 条）。
- **不擅自 git 操作**：commit/push/merge/rebase/reset 需用户显式授权（用户规则第 6 条）。
- **文档语言**：中文。
- **既有不变量优先**：§4 清单高于任何新增便利。
- **Node/pnpm 版本**：与仓库根一致（`^22.19.0 || >=24.0.0`）。

## 6. 成功判据（Definition of Done）

整份计划执行完成，当且仅当：

1. 精选层的所有新增包按仓库清单创建，通过 `pnpm run constraints && typecheck && lint && build && hygiene`。
2. `web-curated` 基线 profile 可启动并通过 profile smoke，且 §4.2 既有用户路径回归矩阵全绿。
3. 每个默认插件均完成静态准入（≥85 分）且同类插件完成动态 A/B 择优。
4. 冲突检测脚本对全量 patch/manifest 零冲突输出。
5. 任一回滚线未被触发，或触发后能自动恢复上一版 lock 与 patch。

> 注：本仓库当前**是** DSH 核心本体。若最终选择将精选层作为独立下游项目交付（而非 monorepo 内包），§3.1 的映射需相应调整；此为已在规划阶段确认的落地目标，不在执行期变更。
