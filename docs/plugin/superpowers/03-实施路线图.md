## 当前实现状态

本节只描述仓库治理基础设施，不能作为下表 P0/P1/P2 rollout 复选框的完成证据。仓库机制、单个候选激活与生态 rollout 的独立完成条件见 [00 §6](00-背景与目标.md)。

五个 profile 模板及其非覆盖式物化路径已经实现。`web-curated` 的目标基线仍为 12 个候选，runtime active 为 0；全部五个 profile 只包含安装自有基础 bundle，并保持 `ignore-scripts=true`，workspace 不生成构建授权或依赖变换。`dsh-web-search-pro`、`dsh-memento`、`dsh-mcp-panel`、`dsh-checkpoint-rewind`、`dsh-lsp-actions` 与 LoongSuite 仅为静态/安装资格候选，因缺少真实固定产物的 keyless assembled runnable snapshot 而保持 inactive；`dsh-web-search-pro` 还缺少必需的 `@anweat/dsh-browser` bundle/runtime dependency。其余候选保留各自的产物、兼容性或安全拒绝。

受管 profile 的 `verify-lock`、observed preflight 与 observed smoke 从 profile manifest、根 pnpm lock、已安装 pnpm lock 快照和已安装包派生来源，并对不一致状态 fail-closed。独立产物根只产生 metadata-only、`observed:false` 结果，包内 `.dsh-curated-artifact.json` 不能建立 observed success。Smoke 校验候选 manifest、bundle patch 与 main 文件存在性，再运行已安装 DSH CLI 的 `--dump-config` 与 `--help`；它不直接导入或初始化候选模块，也不启动 profile runtime 或创建 synthetic shim。候选初始化、真实用户路径和 canary 属于后续独立运行。静态准入按八个维度计算，并校验 Node/core-patch 证据、权威能力冲突规则、元数据 secret、清理后的子进程环境和委托给权限插件的 fail-closed 配置。

仓库没有持久化外部候选完成安装、启用、重启与卸载的 E3 记录。搜索、记忆、浏览器、MCP、真实故障注入与 3–7 天 canary 等长周期评测仍为 pending。计划资产、fixture 和本地组合测试不构成这些工作的完成证据。以下复选框保留为新鲜执行证据清单；已实现机制不自动把旧记录转换为本轮完成状态，长周期项尤其保持未勾选。

### Task P2-2：故障注入（飞书阶段 C）

主动制造故障，通过真实 runtime 运行验证 DSH 能否启动、插件是否 fail-closed、能否禁用单插件恢复、审计是否足够定位。`p2-risk-gates.json` 只允许以下八个场景及其真实 runtime `fail-closed`/恢复结果；资产保持 `planned` 和逐项 `pending`，不记录未运行的 outcome。`smoke-profile.mjs` 只校验产物与 CLI，不能代替本任务的候选初始化或故障执行：

- [ ] 搜索超时、模型 429、浏览器崩溃、SQLite 锁
- [ ] 无权限文件、非法 patch、网络断开、插件初始化异常
- [ ] **验收**：每种故障保留实际 runtime 的启动、初始化、故障结果与恢复产物；后续 canary 使用独立运行记录

- [ ] 故障注入全部 fail-closed 或可单插件禁用恢复。
- [ ] 全部同类 A/B 完成，非补偿门槛无违反。
- [ ] canary 通过、灰度推进无回滚线触发。

## 执行纪律

- **每次只增加一个能力域**，失败回滚锁文件与 profile 快照。
- **不在同一次变更中同时升级 DSH 与插件**。
- 升级采用 canary profile，验证通过后再更新精选 bundle；保留上一个可运行锁文件与 profile 快照。
- 本轮不执行 `git add`，且不改变任务开始前既有 index；commit、push 与 merge 仍需用户显式授权。
