# 03 · 实施路线图（P0/P1/P2 + 叶级门禁）

对应飞书蓝本 §5（实施步骤 A–D）与 §7（推荐落地顺序三批次）。

> **执行者须知**：本路线图供 subagent-driven 或 inline 执行，步骤用 `- [ ]` 复选框跟踪。**叶级门禁**：每个 Verify 步骤是一条耗时 < 1 分钟、可独立判定通过/失败的命令，禁止用整套 `pnpm run test` 代替叶级门禁。**全局约束**（每个任务隐含包含）见 [00-背景与目标.md §5](00-背景与目标.md)。**既有不变量清单**见 [00-背景与目标.md §4](00-背景与目标.md)，实现与 review 逐项举证未破坏。

## 分期与文档阶段映射

| 本路线图 | 飞书阶段 | 目标 | 出口判据 |
|---|---|---|---|
| **P0** 可复现基线与脚手架 | 阶段 A + 第一批 | 建立 `curated` 包组、基线 profile、门禁脚本、低冲突基础栈 | `web-curated` 可启动 + 既有路径回归全绿 |
| **P1** 治理与体验 + 逐域接入 | 阶段 B + 第二批 | 供应链监控、插件市场、会话导出、UI 工作台回归 | 每域静态准入 ≥85 且冲突检测零冲突 |
| **P2** 高能力场景包 + 灰度 | 阶段 C + D + 第三批 | 多 Agent、浏览器、视觉、Office、IM，故障注入与灰度 | canary 3–7 天 + 100 任务 + 无回滚线触发 |

## 当前实现状态

五个 profile 模板及其非覆盖式物化路径已经实现。`web-curated` 的目标基线仍为 12 个候选，当前可准入的 active 基线为 10 个；`dsh-context` 因缺少 Node 兼容证据被拒绝，`dsh-config-manager` 因缺少 profile 级 dry-run 或执行确认控制被拒绝。`web-research` 在这 10 个基线候选上物化已通过目录准入的 `plugin-session-export`；`dsh-mneme`、`dsh-vision-router` 与其他 P2 候选保持 inactive。

`verify-lock`、observed preflight 与 observed smoke 会检查调用方提供的真实解析工件并 fail-closed；smoke 会导入候选主入口，然后运行真实 `--dump-config` 与 `--help`，不创建 synthetic shim。静态准入按八个维度计算，并校验 Node/core-patch 证据、权威能力冲突规则、元数据 secret、清理后的子进程环境和委托给权限插件的 fail-closed 配置。

搜索、记忆、浏览器、MCP、真实故障注入与 3–7 天 canary 等长周期评测仍为 pending。计划资产、fixture 和本地组合测试不构成这些工作的完成证据。以下复选框保留为新鲜执行证据清单；已实现机制不自动把旧记录转换为本轮完成状态，长周期项尤其保持未勾选。

## P0 · 可复现基线与脚手架

### Task P0-1：固定版本与导出官方基线配置

**Files:**
- 读取：仓库根 `package.json`（Node/pnpm 版本范围）
- 产出：`packages/curated/curated-bench/baselines/官方web-dump.txt`（不入 git，记录到 benchmarks）

**Interfaces:**
- Produces：官方 `web` profile 的 `--dump-config` 快照，作为后续 diff 基准

- [ ] **Step 1**：确认 DSH 版本与 Node/pnpm 版本
  - Run: `node -p "require('./package.json').version" && node --version && pnpm --version`
  - Expected：版本落在 `^22.19.0 || >=24.0.0`，输出根包版本
- [ ] **Step 2**：导出官方 `web` profile 配置快照
  - Run: `pnpm dsh --profile web --dump-config > /tmp/官方web-dump.txt 2>&1; wc -l /tmp/官方web-dump.txt`
  - Expected：非空输出，无报错行
- [ ] **Step 3**：记录基线三组任务的启动指标（空任务/简单工具任务/30 分钟稳定运行）
  - Run: `pnpm dsh --profile web --help >/dev/null 2>&1 && echo ok`
  - Expected：`ok`（仅验证 profile 可解析，不启动 server）

> 验证方法：本任务不写代码，只固化基线；`--dump-config` 与 `--help` 均为秒级命令。

## 执行纪律

- **每次只增加一个能力域**，失败回滚锁文件与 profile 快照。
- **不在同一次变更中同时升级 DSH 与插件**。
- 升级采用 canary profile，验证通过后再更新精选 bundle；保留上一个可运行锁文件与 profile 快照。
- 涉及 commit/push/merge 需用户显式授权（用户规则第 6 条）；本目录计划文档不入 git（第 2.4 条）。
