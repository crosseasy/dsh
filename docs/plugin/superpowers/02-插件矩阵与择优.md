# 02 · 插件矩阵与择优

对应飞书蓝本 §2（精选插件矩阵）与 §3（同质插件择优决策）。

> 决策档位定义：**默认** = 进入通用精选 profile；**场景** = 按需启用；**实验** = 完成动态评测后再准入；**不纳入** = 不适合作为当前统一集成的默认能力。所有星标/测试数/CI 数均为 2026-08-24 快照，执行时以实际克隆核验为准。本表的决策档位表示目标用途，不等于当前 active 状态。当前 `web-curated` 目标基线固定为 12 个候选，其中 10 个已准入；每个当前拒绝或 pending 状态以本页 §2 和机器可读 allowlist 为准。

## 2. `web-curated` 目标基线与当前准入

`dsh-toolkit`、`dsh-web-search-pro`、`dsh-context`、`dsh-memento`、`dsh-mcp-panel`、`dsh-smooth-stream`、`dsh-checkpoint-rewind`、`dsh-lsp-actions`、`dsh-permission-rules`、`upstream-radar`、LoongSuite OTel、`dsh-config-manager`。

上述 12 个候选是唯一的 `web-curated` 目标基线定义。当前 10 个已准入并进入模板：`dsh-toolkit`、`dsh-web-search-pro`、`dsh-memento`、`dsh-mcp-panel`、`dsh-smooth-stream`、`dsh-checkpoint-rewind`、`dsh-lsp-actions`、`dsh-permission-rules`、`upstream-radar` 与 LoongSuite OTel；不得表述为 12 个 active。

`dsh-context` 因缺少 Node 兼容证据被拒绝；`dsh-config-manager` 因缺少 profile 级 dry-run 或执行确认配置被拒绝。`plugin-session-export` 已通过目录准入并由 `web-research` 物化，但它是场景候选，不计入 12 个基线候选；`dsh-mneme` 与 `dsh-vision-router` 是 inactive research 候选，长周期评测完成前不进入模板。`dsh-plugin-hub`、`dsh-plugin-guide` 和 `dsh-plugin-check` 同样不计入 12 个目标基线候选。

## 3. 同质插件择优决策

对应蓝本 §3。原则：同一能力域最多一个默认 provider，第二个只能显式 fallback。

### 3.1 插件市场：选 `dsh-plugin-hub`，不同时启用第二个 manager

`dsh-plugin-hub` 是取得 Node 兼容证据后的目标操作面（安装/启停/索引/版本检测/失败回滚）；当前保持 inactive。`dsh-suite/plugin-manager` 作兼容目录与补充数据源。两者同挂会造成设置页重复、安装状态口径不一致、升级竞争；后续激活前者时只离线同步消费后者的兼容数据，不同时加载两个 Web 管理插件。

### 3.2 网页搜索：选 `dsh-web-search-pro`，免费搜索作降级包

`dsh-web-search-pro` 的测试/CI/缓存/抓取/渲染/多平台更完整，作默认 `ctx.web` provider。`dsh-free-web-search` 放无密钥 profile，但缺测试与 CI，不与主 provider 并行注册；降级由配置切换完成，不同时暴露两组高度重叠工具。

### 3.3 记忆：默认 `dsh-memento`，高级实验 `dsh-mneme`

`dsh-memento` 强调有界/审批/审计/协议一致性，作通用默认；profile 明确写入 `writePolicy: ask`、空 `writePolicies` 与 `proposals.enabled: false`，preflight 对不安全值拒绝。`dsh-mneme` 的离线向量、实体时间轴、Sleep Mode、autoDream 更强，但引入后台巩固与模型总结行为，目前保持 inactive，不属于已物化的 `web-research`。Memsearch 与 OpenViking 可用于跨工具共享或大规模 RAG，但父仓库星标不能证明 DSH 适配层成熟度，必须单独做子目录验收。

### 3.4 MCP 管理：选 `dsh-mcp-panel`

`dsh-mcp-panel`（16 测试文件、3 CI、审批门、profile 备份、工具试用台）优于 `dsh-mcp-manager`（无测试无 CI）。后者仅作轻量环境备选，不能同时写同一 MCP 配置。

### 3.5 浏览器：按运行环境二选一

桌面受控自动化优先 `dsh-computer-use`（浏览器/原生控制测试、动作锁定、明确错误处理）；专用隔离浏览器可评估 `dsh-tabbit`，但需额外安装链与许可证核验。共享真实浏览器类更适合人工可接管场景，无测试实现不进无人值守生产 profile。

### 3.6 权限治理：`permission-rules` 在前，`auto-review` 在后

确定性规则对工具名/参数/路径/Agent 身份做可审计判断；AI review 处理无法静态编码的灰区。精选层校验外部权限插件的真实 bundle 配置必须设置 `badFilePolicy: fail` 与 `enforce: true`，实际工具权限决策仍委托给该插件。执行顺序固定：

```text
核心沙箱 → permission-rules → 高风险人工审批/auto-review → 工具执行 → 结果审计
```

任何 LLM 超时、解析失败或模型不可用都 **fail-closed**。

## 4. 能力域互斥表（capability-conflicts 的种子）

| 能力域 | 默认 provider | 允许的 fallback | 互斥规则 |
|---|---|---|---|
| 网页搜索 | `dsh-web-search-pro` | `dsh-free-web-search`（配置切换） | 不同时注册两组搜索工具 |
| 记忆 | `dsh-memento` | `dsh-mneme`（研究 profile） | 不同时启用两套自动记忆注入 |
| MCP 管理 | `dsh-mcp-panel` | `dsh-mcp-manager`（轻量环境） | 不同时写同一 MCP 配置 |
| 浏览器 | `dsh-computer-use` | `dsh-tabbit`（隔离，实验） | 同 profile 只启用一种浏览器控制 |
| 多 Agent 编排 | `dsh-agent-team-gui` | `dsh-background-agents`（二选一） | 同 profile 只启用一种主编排器 |
| 上下文压缩 | `dsh-context`（观测） | `dsh-context-doctor`（只读诊断） | 不与多个自动压缩插件长期并存 |
| 桌面客户端 | 二选一 | `Martty` / `deepseek-harness-desktop` | 不同时部署两个桌面壳 |

> 该表是 [01-目标架构.md](01-目标架构.md) 中 `curated-policy` 的 `capability-conflicts.yaml` 的内容来源，preflight 脚本据此拒绝同域双 provider。
